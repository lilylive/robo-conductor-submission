# 検証記録

実施日：2026-10-31。macOS 26.5.2 arm64、Python 3.11.15、pybullet-arm64 3.2.8、numpy 2.4.6、imageio 2.38.1、imageio-ffmpeg 0.7.0。公式pybullet 3.2.7はこの環境のソースビルドが失敗したため、Macは別途保守されるフォークを使用。

## 実施した確認

- 基礎プログラムの `robo_conductor.py` のSHA-256は、保存した元ファイルと開発版の双方で `78cafda41665f37fa9b3c2ac706d9f36164308708925a99eca9df1abfbb0e1b8` と一致。
- 保存済みの計画で元コードを実行。320×192、24 fps、4動作、約6.96秒、H.264。APIは呼び出していない。元コードは接触でなく位置の近接を記録。
- 改良版を640×360、30 fpsで実行。3つの手動パターン、計24打中24打で対象パッドとの正の法線力を検出。接触開始24件、対象外パッドへの接触0件。37.00秒、H.264、AAC 48 kHz。全フレームのデコードに成功。接触時の赤パッドの色変化を静止画像で確認。
- フルHD版も1920×1080、30 fps、37.00秒、H.264＋AACで生成。24打すべてで対象パッドとの接触を検出し、誤パッド接触0件。映像・音声の全デコードに成功し、接触時の色変化を静止画像で確認。
- `python -m unittest discover -s tests -v`：3テスト成功。赤の連打を含む4打の実シミュレーション、計画の検証、接触がないイベントの音声生成を確認。
- 追加の負例としてパッドを遠方に移動：接触成功0件、接触イベント0件、生成WAVは無音。3色の診断では、力を伴うパッド接触はいずれもロボットのリンク6に限られた。

記録した初回の接触力は約1,439〜2,183 N。モーター設定等に依存する未較正のシミュレーション値で、実機の打撃力や安全性は示さない。
